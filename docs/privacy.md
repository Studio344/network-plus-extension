# Privacy notice for Network+ for DevTools

Last updated: 2026-11-17

## Scope

Network+ for DevTools is a Microsoft Edge and Google Chrome DevTools extension for inspecting HTTP requests, responses, and WebSocket messages from the page being debugged. This notice describes the extension behavior in the current repository version. It does not make a legal guarantee or replace a user's responsibility to handle network evidence safely.

## Data Network+ can access

When the Network+ panel is open, the browser's DevTools network API can provide URLs, query values, request and response headers, cookies, request bodies, response bodies, timing phases, sizes, status codes, initiator information, and related DevTools metadata. This data can contain personal, authentication, financial, health, location, communication, confidential, or otherwise sensitive information from the inspected page.

Network+ processes this evidence locally in the DevTools panel so the user can display, filter, search, compare, inspect, copy, import, and export it. The local-only sample capture uses deterministic `.test` domains and sends no network request.

## Collection and transmission

Network+ keeps captured traffic on your device. It has no telemetry, analytics, advertising, account service, external API, or remote SDK. It observes traffic generated by the inspected page; that page's own network destinations and privacy practices are separate from Network+.

The toolbar's `Report a problem` link opens Google Forms in a new tab when selected. The link includes only the display language and the available Network+ version, browser name and major version, and OS family. Google receives these values when you open the link. You can review or clear the optional environment field before you submit the form. Your report is shared with the developer when you submit it, subject to Google's own privacy practices.

No developer receives or reads inspected traffic through the extension. Users who choose the public support route submit their posts directly to GitHub and should remove credentials and sensitive traffic beforehand.

## Chrome Web Store limited use

Network+ uses inspected-page data only to provide its clearly disclosed, user-facing network inspection, filtering, search, comparison, retention, clipboard, import, and export features. It does not use this data for advertising, profiling, creditworthiness, or any unrelated purpose.

Network+ does not sell or transfer inspected traffic to the developer or to third parties, and it does not permit human access to inspected traffic through the extension. A user can independently choose to copy or export data, follow an external support link, or post information to GitHub; those actions occur only at the user's direction and should be reviewed by the user first.

## Local preferences

Network+ stores only UI preferences locally:

- The selected System, Dark, or Light theme is stored through `chrome.storage.local`, with panel local storage used as a fallback.
- The selected language for explanatory text and dialogs (System, English, or Japanese) is stored the same way. Toolbar button labels and column headers stay in English, and the choice affects display only.
- One-time guide dismissals — currently the mirror tab's undock explainer — are stored in panel local storage as a flag.
- Search preferences — the search scope checkboxes, the case / whole-word / regular-expression match options, and the Matches only state — are stored through `chrome.storage.local` as booleans. Search keyword text is never stored.
- The retention setting, column order, visibility, and widths, the configured header-column name, and the domain-summary visibility flag are stored in panel local storage.
- The saved view preset stores column visibility and filter-rule values entered by the user. It does not store captured request or response records, headers, or bodies, but a user-entered filter value can itself contain text such as a domain or path.

Search results, selected rows, captured request records, headers, and bodies are not written to persistent storage by Network+.

## Retention and user controls

The DevTools panel holds its working set in memory. Request rows are retained without a count limit by default. The Settings dialog explains the memory cost and lets users set a limit from 100 to 100,000 rows. The shared HTTP response cache keeps up to 1 MiB per body and 32 MiB in total. Old requests or bodies can be evicted when limits are reached.

Live WebSocket capture keeps recent long text messages in the inspected page's memory, up to 8 Mi UTF-16 code units. This makes it possible to save complete messages while showing short previews in the panel. Stopping or clearing the capture, starting a new capture session, and leaving the inspected document release the retained text. Newer messages can also evict older ones. If the panel closes without clearing the capture, the page can retain the text until the document or capture session changes.

`Clear` removes the current working set from the panel and keeps one bounded Undo snapshot for up to 10 seconds. Retention pressure can release some or all of that snapshot earlier. After the Undo window expires, Network+ releases the retained snapshot. Closing DevTools ends the in-memory panel session. Clear and closing DevTools do not delete files the user already downloaded or text the user already placed on the system clipboard.

## Clipboard and HAR output

Network+ writes to the clipboard or creates a local download only after the user selects a copy, save, or export action. Sanitized output is the default. It redacts URL query and form-like fragment values, URL credentials, cookie values, and header values outside a small structural allowlist. It defensively redacts selected JSON fields and omits body formats it cannot safely sanitize. Users should review output before sharing it because some sensitive values may remain.

Full output can include URLs, headers, cookies, request bodies, response bodies, captured WebSocket frames, and authentication or personal information. Whenever you choose a full HAR export, a full body copy, or a complete HTTP body or WebSocket message download, Network+ shows a warning and asks for one-time confirmation for that action. Saving an available complete HTTP response can retrieve a body larger than the shared cache allows. The row menu labels its collapsed group of full copy formats `Copy full (unsanitized)`. Network+ does not save a preference to use full output automatically.

Edit and resend sends a request only after the user chooses to send it. The destination must have the same scheme, host, and port as the inspected page. The browser may ask for optional scripting and access to that site when the user resends. A packaged script runs in an isolated context of the inspected document so the browser can use that site’s session when requested. The request fields are not passed to the page’s JavaScript. Network+ blocks redirects and does not store the composed request. JWT-shaped header values decode locally for display only. The decoded claims are never verified, stored, copied, or exported.

The Keyboard Shortcuts dialog also provides `Copy safe support summary`. Network+ builds this summary only after that button is selected and copies only the packaged Network+ version, Microsoft Edge major version when identifiable (`unknown` in other browsers), coarse OS family, normalized theme and retention settings, recording and local-sample state, and color-scheme and reduced-motion preferences. It does not inspect or include captured traffic, captured or visible request counts, URLs, headers, cookies, bodies, search or filter values, storage contents, logs, the full user agent, identifiers, credentials, or file paths. The summary states that it excludes captured traffic and must be reviewed before posting.

Imported HAR or SAZ files are processed locally and become part of the same bounded in-memory working set. Network+ does not upload imported files.

## Optional support links

The panel toolbar includes an optional `☕` button that opens a Support dialog. The dialog contains no payment form, no third-party script or frame, and no embedded checkout, and it performs no network request. It offers two outbound links, https://github.com/sponsors/himiyosh and https://himiyosh.gumroad.com/coffee, each as a button that opens that page in a browser tab. The dialog writes nothing to the clipboard and stores no state about itself. Any payment is completed on the destination site under that site's own terms and processing; no payment, account, or card data is entered into, handled by, or visible to Network+.

Following a link opens the destination in a normal browser tab, where that site's own privacy practices and payment processing apply. Network+ sends those sites no captured traffic, no usage data, and no identifier, and it receives nothing back from them. It cannot determine whether a user opened a link or contributed, and it stores no state about the dialog. Every Network+ feature remains available regardless of whether a user contributes.

## Support

To file a bug report with the developer, choose `Report a problem` from the Network+ toolbar menu and describe what happened in Google Forms. Questions and public reports can be filed at https://github.com/himiyosh/network-plus-extension/issues/new/choose. The reviewed output from `Copy safe support summary` is optional for GitHub Issues. Keep raw traffic, credentials, customer data, full HAR files, and other sensitive material out of both routes.

## Policy changes

This notice should be reviewed when data access, storage, export, permissions, or external-service behavior changes. The update date at the top records the latest repository review; it is not a claim that Microsoft, Google, or either extension store has reviewed or approved this notice.
